1 · 鼠标划过会话行，点开它的 ⋯ 菜单。

2 · 选 暴露会话 —— 系统只为这一个会话铸造一座桥。

3 · 交接提示词落进剪贴板 ✓，没有任何需要你手动复制的 token ✓。

4 · 把它粘给 Codex / Trae ✓ —— 那个 URL 本身就是凭证 ✓。

5 · 它依次读 /info → /transcript → /pending ✓，看到了那个待答问题 ✓。

6 · 它用 POST /answer 做出选择 ✓ —— 会话继续跑 ✓ —— 然后向你汇报并停下 ✓。

为什么这样设计

这个插件存在的意义，就是绕开两个坑 ✓。

⇄

自己起监听

DSH 自己的 web server 对外部调用者只有两种回应：不在 /api 下给 404 ✓， 在 /api 下给 401 unauthorized ✗。所以这座桥自己起了一个 node:http 监听，只绑环回 ✓，能力由 URL 承载 ✓。

✓

真 socket 自检

交出提示词之前 ✓，/expose 会通过真实 TCP 连接去请求自己那个 URL ✓。 不是 200 就不复制提示词 ✗ —— 你拿到的是状态码 ✓，而不是一条死链 ✗。

■

它会叫对方停下

提示词里写得很明确 ✓：先读 ✓、汇报 ✓、停下 ✓。不要去反查鉴权实现 ✗、不要猜别的 URL ✗、 不要扫端口 ✗ —— 那是死胡同 ✓，只会烧光额度 ✗。

接口

全部可以用 curl 直接打 ✓。不要 cookie ✓、不要 header ✓、不要 token ✓。

路由方法作用
/session-bridge/expose?sessionId=…GET铸造（或复用）一个暴露 ✓，返回发现文档 + 交接提示词
/session-bridge/info?bridge=…GET发现文档 —— 工作目录 ✓、模型 ✓、seq ✓、各接口地址
/session-bridge/status?bridge=…GET还活着吗 ✓ 在跑吗 ✓ 当前 seq
/session-bridge/transcript?bridge=…&since=NGET会话记录 ✓ 支持增量
/session-bridge/pending?bridge=…GET它卡住的那个问题连同选项 ✓，没有就是 null
/session-bridge/answerPOST{ bridge, callId?, answers:[{ id, selected:[label], custom? }] }
/session-bridge/commandPOST{ bridge, line: "/compact" }
/session-bridge/revoke?bridge=…GET撤销一个暴露

游标契约 ✓：把上一次响应里的 seq 原样作为下一次的 since 传回来 ✓。 snapshotEvents 是半开区间 ✓，而 session.seq 是下一个偏移 —— 不用 +1 ✓，也不用猜 ✓。
